# Backend Developer for SaaS Platform — SPEC.md

## 1. Concept & Vision

A production-ready backend for a multi-tenant SaaS platform built with **FastAPI** (Python 3.11+), designed for horizontal scalability. The system exposes REST APIs with JWT authentication, supports real-time WebSocket feeds, uses PostgreSQL for relational data, and Apache Kafka for event-driven inter-service communication. Every component is containerised with Docker and deployable to any cloud provider (AWS/GCP/Azure).

```
                           │

                 └─────────┬──────────┘
                           │
                 ┌─────────▼──────────┐
                 │   Apache Kafka      │
                 │  (event bus / queues)
                 └────────────────────┘
```

**Multi-tenancy strategy:** PostgreSQL **row-level security (RLS)** with a `tenant_id` foreign key on every table. A middleware injects the current tenant context from the JWT `tenant_id` claim into `request.state`. Queries are automatically scoped. No shared tables between tenants.

## 4. Data Model

### Core Tables (per tenant via RLS)

```sql
-- Tenants
CREATE TABLE tenants (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    name VARCHAR(255) NOT NULL,
    slug VARCHAR(63) UNIQUE NOT NULL,
    plan VARCHAR(31) DEFAULT 'starter',
    created_at TIMESTAMPTZ DEFAULT NOW()
);

-- Users (tenant-scoped)
CREATE TABLE users (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    tenant_id UUID NOT NULL REFERENCES tenants(id),
    email VARCHAR(255) NOT NULL,
    password_hash VARCHAR(255) NOT NULL,
    role VARCHAR(31) DEFAULT 'member',
    is_active BOOLEAN DEFAULT TRUE,
    created_at TIMESTAMPTZ DEFAULT NOW(),
    UNIQUE(tenant_id, email)
);

-- API Keys (for service-to-service auth)
CREATE TABLE api_keys (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    tenant_id UUID NOT NULL REFERENCES tenants(id),
    key_hash VARCHAR(255) NOT NULL,
    name VARCHAR(127),
    last_used_at TIMESTAMPTZ,
    created_at TIMESTAMPTZ DEFAULT NOW()
);

-- Projects (tenant-scoped)
CREATE TABLE projects (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    tenant_id UUID NOT NULL REFERENCES tenants(id),
    name VARCHAR(255) NOT NULL,
    description TEXT,
    status VARCHAR(31) DEFAULT 'active',
    created_at TIMESTAMPTZ DEFAULT NOW()
);
```

### Row-Level Security

```sql
ALTER TABLE users ENABLE ROW LEVEL SECURITY;
ALTER TABLE projects ENABLE ROW LEVEL SECURITY;

CREATE POLICY tenant_isolation ON users
    USING (tenant_id = current_setting('app.tenant_id')::UUID);

CREATE POLICY tenant_isolation ON projects
    USING (tenant_id = current_setting('app.tenant_id')::UUID);
```

## 5. API Integration Specifications

### 5.1 REST API (`/api/v1/`)

| Endpoint | Method | Auth | Description |
|---|---|---|---|
| `/auth/register` | POST | — | Register tenant + admin user |
| `/auth/login` | POST | — | Returns JWT access + refresh tokens |
| `/auth/refresh` | POST | — | Refresh access token |
| `/users` | GET | JWT | List tenant users (paginated) |
| `/users` | POST | JWT | Create user |
| `/users/{id}` | GET | JWT | Get user by ID |
| `/users/{id}` | PUT | JWT | Update user |
| `/users/{id}` | DELETE | JWT | Soft-delete user |
| `/projects` | GET | JWT | List projects (paginated) |
| `/projects` | POST | JWT | Create project |
| `/projects/{id}` | GET | JWT | Get project |
| `/projects/{id}` | PUT | JWT | Update project |
| `/projects/{id}` | DELETE | JWT | Delete project |

**Pagination:** `?page=1&per_page=20` → `{data: [...], total: N, page: 1, per_page: 20}`.

### 5.2 WebSocket (`/ws/v1/`)

- **Auth:** JWT passed as query param `?token=<jwt>` or first WS frame containing `{token: "<jwt>"}`.
- **Scope:** Subscribe to tenant-scoped channels only.
- **Channels:** `tenant.{tenant_id}.projects`, `tenant.{tenant_id}.users`.
- **Redis Adapter:** Redis Pub/Sub used when scaling to multiple Uvicorn workers.

### 5.3 Kafka Events

Events published on: `saas.{environment}.tenant.{tenant_id}.{entity}.{action}`

```json
{
  "event_id": "uuid",
  "tenant_id": "uuid",
  "entity": "project",
  "action": "created",
  "payload": { ... },
  "timestamp": "ISO8601"
}
```

Consumers: audit log writer, notification service, analytics pipeline.

## 7. Authentication & Authorisation

- **JWT Access Token:** 15-min expiry, contains `{sub: user_id, tenant_id, role}`.
- **JWT Refresh Token:** 7-day expiry, stored in HTTP-only cookie.
- **Password hashing:** argon2 (via argon2-cffi).
- **Role-based access:** `admin > member > viewer`. Endpoints decorated with `@require_role("admin")`.
- **Multi-tenancy isolation:** `tenant_id` enforced at DB query level via RLS; no cross-tenant data leakage possible even if code has bugs.

## 11. Acceptance Criteria

1. `/auth/register` creates a new tenant + admin user in one call.
2. Login returns valid JWT; expired tokens are rejected with 401.
3. Users created under Tenant A cannot read Tenant B's data (RLS enforced).
4. WebSocket connections fail without a valid JWT.
5. Kafka receives an event on every create/update/delete of a project.
6. Docker Compose starts the full stack (app + DB + Kafka + Redis) in one `docker compose up`.
7. All REST endpoints have OpenAPI docs auto-generated at `/docs`.
8. pytest passes with >80% coverage on core services.
